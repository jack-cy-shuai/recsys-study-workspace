# GitHub Publishing Guide

This document suggests how to present this project on GitHub.

## Recommended Repository Names

Recommended:

- `recsys-study-workspace`

Other good options:

- `recsys-paper-reproduction`
- `lightgcn-study-lab`
- `recsys-research-notes`

### Best Choice for the Current Project

Use `recsys-study-workspace` if you want the repository to contain all of these together:

- papers
- reproduction code
- notes
- experiment records

Use `lightgcn-study-lab` only if you want the repository to focus mostly on the current LightGCN line.

## Suggested GitHub Description

Recommended short description:

`A personal recommender-systems study workspace with paper reading notes, LightGCN reproduction code, and experiment tracking.`

Alternative:

`Recommender systems learning workspace: papers, code reproduction, notes, and experiments.`

## Suggested Topics

Recommended GitHub topics:

- `recommender-systems`
- `collaborative-filtering`
- `lightgcn`
- `paper-reproduction`
- `pytorch`
- `graph-neural-networks`
- `llm-recommender`

## Suggested README Opening

You can use this style at the top of the GitHub repository:

> A personal research workspace for recommender systems. This repository collects classic and recent papers, a minimal LightGCN reproduction, reading notes, and experiment records.

## Suggested Long-Term Organization

As the project grows, keep this pattern:

- `papers/` for source papers
- `notes/` for your own understanding
- `docs/` for polished summaries and roadmaps
- `experiments/` for reproducible experiment logs
- code folders for runnable implementations

## Suggested Commit Style

Good commit message examples:

- `add lightgcn baseline reproduction`
- `organize paper library and normalize filenames`
- `add notes template for paper reading`
- `record baseline experiment results`
- `implement top-k evaluation for lightgcn`
