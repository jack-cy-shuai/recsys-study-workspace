## 三、基线模型实现质量评估

### LightGCN（自实现，`lightgcn/model.py`）

**算法正确性评估：**

1. **Embedding 初始化**：✅ 使用 `nn.init.normal_(std=0.1)`，与原论文一致
2. **图传播**：✅ `torch.sparse.mm(norm_adj, x)` 每层稀疏矩阵乘法实现消息传递
3. **归一化**：✅ D^{-1/2} A D^{-1/2} 对称归一化，无误
4. **层聚合**：✅ 所有层 embedding 求平均（`torch.stack(layer_outputs).mean(dim=0)`）
5. **预测**：✅ 内积 `user_emb @ item_emb.t()`
6. **BPR Loss**：✅ `-log(sigmoid(pos - neg))` 形式正确

**潜在问题：**

- BPR loss 中正则化用的是原始 embedding 而非传播后的 embedding（`self.user_embedding(users)` 而非 `user_emb[users]`）。这在一些实现中确实如此（LightGCN 论文 Section 3.3），但需要确认是否为有意设计。
- `compute_embeddings()` 在 `bpr_loss` 的每个 batch 中都会重新计算，即使同一个 epoch 内图结构不变。如果 embedding dim 较大且层数多，这会显著影响训练效率。应该在一个 epoch 内缓存最终 embedding，只在 epoch 开始时更新一次。
- 稀疏矩阵乘法 `torch.sparse.mm` 在 CPU 上效率较低，但功能正确。

**RecBole 运行的 BPR/NeuMF/LightGCN：**

这些不是自实现，是直接调用 RecBole 的 `run_recbole()`。**这违反了你在项目规范中设定的"绝对不要引入 RecBole"准则。** RecBole 的结果只能作为参考基准，不能替代自实现。

**ml-100k 上的 RecBole 对比结果（仅供参考）：**

| 模型 | Val MRR@10 | Test Recall@10 | Test NDCG@10 |
|------|-----------|----------------|--------------|
| BPR | 0.4071 | 0.2488 | 0.2882 |
| LightGCN | 0.3965 | 0.2378 | 0.2786 |
| NeuMF | 0.3789 | 0.2273 | 0.2657 |

注意：这些结果来自 RecBole，不代表自实现的质量。一旦完成自实现，结果应该与这些数值接近（在合理波动范围内）。

## 四、实验数据状态

### 合成数据集问题

当前唯一的训练数据是 `make_basic_dataset.py` 生成的人工数据：
- 60 用户，120 物品，600 交互
- 每个用户的主偏好组 + 相邻组构造
- 每个用户固定 8 train / 1 val / 1 test

**这个数据集仅适合 smoke test（验证代码能跑通），完全不能用于任何有意义的实验。**

### metrics.json 与实验报告的不一致

- `artifacts/basic_run/metrics.json` 仅记录 1 个 epoch（Recall@10=0.1667）
- `experiments/exp_001_lightgcn_baseline.md` 声称训练了 80 个 epoch，best epoch=61，Recall@10=0.5833

这说明 metrics.json 可能是更早期的运行结果，后来的运行结果覆盖了 best_model.pt 但没有更新 metrics.json（或 metrics.json 被旧版本覆盖）。

建议首先接入 MovieLens-100K（已在 RecBole 中使用）和 MovieLens-1M，并实现标准的留一法（leave-one-out）评估。
